# Scripting Guidelines for Antigravity Skills

`[DARKCODE::REFERENCE::SCRIPTING_GUIDELINES::v1.0]`

## 1. Role of Scripts in Agent Skills

Skills should not rely solely on the AI agent typing speculative shell one-liners or multi-step command substitutions. Complex, brittle, or error-prone sequences must be codified into executable scripts inside `scripts/`.

### Benefits of Encapsulated Scripts:
1. **Deterministic Execution**: The agent executes a tested utility with validated arguments.
2. **Command Approvals & Sandboxing**: Simplifies prefix-matching in sandbox environments.
3. **Structured Outputs**: Scripts can output machine-readable JSON that agents parse directly without regex scraping.

---

## 2. Core Engineering Standards

### A. Living-Off-The-Land (Zero Pip Dependencies)
Helper scripts must execute in diverse agent environments without requiring ad-hoc `pip install` commands:
- Use Python standard library modules (`pathlib`, `argparse`, `subprocess`, `json`, `ast`, `os`, `sys`, `shutil`, `re`, `tarfile`).
- If an external dependency is mandatory (e.g. `frida`, `rizin`), detect its presence gracefully and emit an actionable remediation message if missing.

### B. Command-Line Interface (CLI) Design
Every helper script must implement a standardized CLI using `argparse`:
- Provide descriptive `--help` docstrings.
- Include an action/subcommand paradigm (`--action [run|inspect|validate|extract]`).
- Always support a `--json` flag to return structured diagnostic output.
- Support a `-v` / `--verbose` flag for detailed stderr tracing.

### C. Hashbangs & File Permissions
- All scripts must start with an appropriate hashbang:
  ```python
  #!/usr/bin/env python3
  ```
  or
  ```bash
  #!/usr/bin/env bash
  ```
- All scripts must be marked executable (`chmod +x <script>`) during scaffolding and installation.

### D. Return Codes & Exit Semantics
- Return `0` strictly for clean execution.
- Return non-zero (`1`, `2`) for failures.
- When an error occurs, write human-readable diagnostics to `sys.stderr` and structured error JSON to `sys.stdout` if `--json` was requested.

---

## 3. Sandboxing & Path Awareness

Antigravity executes commands inside sandbox containers by default:
- Do NOT hardcode machine-specific paths like `/home/user/` or `/tmp/` unless dynamically resolved via `tempfile` or relative to the workspace.
- For artifacts generated by the skill, place them within:
  - The current working directory (`Path.cwd()`)
  - A designated `--output` directory provided by the agent
  - The agent's scratch directory (`<appDataDir>/brain/<conversation-id>/scratch/`)

---

## 4. Standard Python Helper Template

```python
#!/usr/bin/env python3
import sys
import os
import json
import argparse
from pathlib import Path

def execute(target: str, action: str) -> dict:
    # Deterministic logic
    return {
        "status": "success",
        "action": action,
        "target": target,
        "payload": {}
    }

def main():
    parser = argparse.ArgumentParser(description="Deterministic skill execution utility")
    parser.add_argument("--action", choices=["execute", "inspect", "clean"], default="execute")
    parser.add_argument("--target", default=".", help="Target file or directory")
    parser.add_argument("--json", action="store_true", help="Machine-readable output")
    args = parser.parse_args()

    try:
        res = execute(args.target, args.action)
        if args.json:
            print(json.dumps(res, indent=2))
        else:
            print(f"[+] Result: {res['status']}")
        sys.exit(0)
    except Exception as e:
        if args.json:
            print(json.dumps({"status": "error", "error": str(e)}))
        else:
            print(f"[-] Execution failure: {e}", file=sys.stderr)
        sys.exit(1)

if __name__ == "__main__":
    main()
```
